# Storybook у цьому проєкті

Storybook показує токени й компоненти дизайн-системи окремо від сайту. Це єдине місце, де студент переглядає систему: тимчасових сторінок-перевірок у проєкті не створюй. Студент — нетехнічний дизайнер-початківець. Пояснюй простими словами, не вимагай знати API Storybook, після кожного кроку коротко кажи, що зроблено.

## Перед початком

1. Прочитай `CLAUDE.md` у корені: стек, правила роботи з Git, токени, список компонентів, правила. Якщо `CLAUDE.md` немає, скажи студенту й запропонуй створити заготовку, перш ніж продовжувати.
2. Токени оголошені в блоці `@theme` у головному файлі стилів (зазвичай `app/globals.css` або `src/app/globals.css`, шлях звір із проєктом). Це єдине джерело значень.
3. Перевір, чи Storybook уже є: тека `.storybook` і скрипт `storybook` у `package.json`.
4. Працюй у поточній гілці (`main`). Нових гілок не створюй, поки студент прямо не попросить.

## Токени системи

Цей розділ описує токени саме цього проєкту. Якщо назви тут не збігаються з `@theme`, правдою вважай `@theme` і скажи студенту, що розділ треба оновити.

- Кольори (`--color-*`, ролі, не відтінки): `canvas` (фон сторінки; текст на заливці accent), `surface` (картки), `line` (лише декор: розділювачі, рамки карток і chips), `accent` (кнопка, посилання, eyebrow, фокус), `accent-hover` (заливка основної кнопки при hover), `text` (основний текст), `text-muted` (другорядний текст), `danger` (помилка: текст і межа поля). Класи: `bg-canvas`, `bg-surface`, `border-line`, `bg-accent`, `hover:bg-accent-hover`, `text-accent`, `text-text`, `text-text-muted`, `border-text-muted`, `text-danger`, `border-danger`; текст на заливці accent — `text-canvas`. Dark за замовчуванням, Light вмикається атрибутом `data-theme="light"` на `<html>` (ті самі змінні, інші значення).
- Межа поля форми й кнопки без заливки: `text-muted` (контраст не менше 3:1), не `line`.
- Радіуси (`--radius-*`): `rounded-control` (кнопки, поля, chips, перемикач, портрет), `rounded-card` (картки, смуга реалізацій).
- Розміри тексту (`--text-*`): `text-display` (h1), `text-heading` (h2), `text-lead` (лід), `text-lead-strong` (назва в картці), `text-body` (основний текст), `text-body-strong` (кнопка, пункт меню, посилання), `text-caption` (підпис, chip), `text-caption-strong` (мала кнопка, перемикач мови), `text-label` (eyebrow; регістр капсом додає `uppercase`). Висота рядка, трекінг і жирність задані парами в `@theme` (`--text-*--line-height`, `--text-*--letter-spacing`, `--text-*--font-weight`), тож окремо їх не задають.
- Пропорції картинок (`--aspect-*`): `aspect-portrait` (портрет, 1 / 1), `aspect-cover` (обкладинка роботи, 4 / 3).
- Шрифт (`--font-sans`): DM Sans, клас `font-sans`. Підключений у `src/app/fonts.ts` через `next/font` (підмножини `latin` і `latin-ext`).
- Токени розкладки, лише для сторінок, не для компонентів: `max-w-page` (`--container-page`, ширина контенту) і `py-section` (`--spacing-section`, відстань між секціями, на мобільному менша). Поля сторінки: `px-16` на десктопі, `px-4` на мобільному.
- Відступи: тільки 8, 12, 16, 24, 32 px, тобто числа 2, 3, 4, 6, 8 у класах (`p-2`, `gap-4`).

Усе, що є в історіях, документації й компонентах, будується тільки з цього. Заборонено: hex і rgb, стандартні класи Tailwind поза системою (`bg-blue-600`, `text-sm`), значення в квадратних дужках (`p-[13px]`, `h-[150px]`), відступи поза набором. Після скидання стандартної палітри класи `text-white`, `bg-black`, `bg-white` і подібні мовчки перестають працювати: Tailwind не повідомляє про невідомий клас. Тому після кожної зміни перевіряй, що в коді немає класів, яких немає в `@theme`. Якщо історії чи документації потрібен елемент, якого немає в системі, не вигадуй його: перелічи, чого бракує, і запитай студента.

## Налаштування, якщо Storybook ще немає

1. У корені проєкту запусти:

   ```
   npm create storybook@latest -- --features docs a11y --type nextjs --builder vite --no-dev
   ```

   Потрібен Node.js 20 або новіший. Фреймворк вийде `@storybook/nextjs-vite`. У Claude Code діалогу ініціалізації немає, тому всі прапорці передаються одразу. НЕ використовуй прапорець `--yes`: він вмикає всі можливості, включно з тестами. Скажи студенту, що саме додалося.
2. Одразу після ініціалізації:
   - у `.storybook/main` прибери `staticDirs: ['../public']`, якщо він там є. Storybook збирається в `public/storybook`, і з цим рядком збірка падає з помилкою `ERR_FS_CP_EINVAL`;
   - у `package.json` зафіксуй версію `vite` конкретним числом замість `"latest"`;
   - видали приклади історій, які створила ініціалізація (Button, Header, Page, теку `stories` з ними): вони не належать проєкту.
3. **Tailwind у Storybook.** Next.js підключає Tailwind через свій збирач, а Storybook працює на Vite і цих стилів не бачить: без цього кроку компоненти в історіях без стилів. Встанови `npm i -D @tailwindcss/vite` і в `.storybook/main` додай плагін:

   ```ts
   import tailwindcss from "@tailwindcss/vite";
   // …
   viteFinal: async (config) => {
     config.plugins = [...(config.plugins ?? []), tailwindcss()];
     return config;
   },
   ```

4. У `.storybook/preview` імпортуй головний файл стилів з токенами (наприклад, `import '../app/globals.css';`, шлях звір із проєктом).
5. **Шрифти в Storybook.** `next/font` віддає змінні шрифтів класами на `<html>` у layout, а Storybook layout не бачить. Винеси підключення шрифтів в окремий файл `fonts.ts` поруч із layout (наприклад, `app/fonts.ts`), імпортуй його і в layout, і в `.storybook/preview.tsx`, і в preview додай класи змінних шрифтів на `<html>` (`document.documentElement.classList.add(...шрифт.variable.split(" "))`). Декоратор історій для цього не підходить: він не діє на сторінки docs (MDX), а Tailwind бере `font-family` саме з `<html>`. Підмножини (`subsets`) бери ті, що шрифт справді має: перед додаванням `cyrillic` перевір список у `node_modules/next/dist/compiled/@next/font/dist/google/font-data.json`. Якщо підмножини немає (DM Sans має лише `latin` і `latin-ext`), не додавай її: збірка впаде. Тоді кирилиця показується запасним шрифтом, а для українських коментарів у Storybook підбери пару за розділом «Українські коментарі в Storybook».
6. Якщо аддона доступності ще немає: `npx storybook add @storybook/addon-a11y`.
7. Стартові стилі й тема `create-next-app`: змінні `--background` і `--foreground`, медіазапит темної теми, шрифти Geist. Якщо вони заважають системі токенів (перебивають `canvas` та `text`, підміняють шрифт), прибери їх і скажи студенту, що саме видалено. Якщо не заважають, не чіпай.
8. Не вмикай і не підключай те, що ініціалізація пропонує додатково: Vitest, Playwright, MCP-аддон (`@storybook/addon-mcp`), Chromatic, команду `storybook skills setup`. Якщо вони з'явилися в проєкті, скажи студенту й запитай, що робити.
9. У `package.json` мають бути скрипти: `storybook` (запуск, `npm run storybook`) і скрипт збірки для публікації (див. нижче).
10. Одразу зроби сторінку «Токени» (див. нижче): це перша перевірка, що токени й шрифти в Storybook підхопились.

## Сторінка «Токени»

MDX-файл (наприклад, `Tokens.mdx`, `title` латиницею: `Foundations/Tokens`) з блоками `ColorPalette` і `ColorItem` (кольори) та `Typeset` (шкала шрифтів) з `@storybook/addon-docs/blocks`. Для радіусів, пропорцій і відступів готових блоків немає: зроби прості зразки (плашки з класами `rounded-control`, `rounded-card`, `aspect-cover`, квадрати з кроками відступів). Значення не вписуй: у `colors` передавай змінні, наприклад `var(--color-accent)`. Оновлюй сторінку щоразу, коли змінюється `@theme`.

## Українські коментарі в Storybook

Сайт польською або англійською, тому в самому сайті українського тексту немає. Українські підписи, описи й пояснення в Storybook потрібні тільки студенту, щоб легше читати систему. Вони не частина дизайну, тому мають одразу відрізнятися від справжніх текстів сайту:

- **Заголовки** українською пиши звичайним накресленням, без курсиву.
- **Пояснення й описи** (притемнені, `text-text-muted`) пиши курсивом (клас `italic` або `<em>`).
- **Не курсивом**: назви токенів і класів (`accent`, `text-display`), код, зразки шрифтів і текстів мовою сайту (польською чи англійською).
- **Шрифт.** Якщо шрифт сайту не має кирилиці, додай шрифт-пару лише для Storybook: файл `.storybook/fonts.ts` через `next/font/google` з `subsets: ['cyrillic']` і змінною на кшталт `--font-storybook-cyrillic`. Бери нейтральний шрифт із кирилицею, схожий за формою на шрифт сайту (для DM Sans це Manrope). У `.storybook/preview.tsx` додай його клас на `<html>` і допиши змінну в `--font-sans` після шрифту сайту: `document.documentElement.style.setProperty("--font-sans", "var(--font-dm-sans), var(--font-storybook-cyrillic), ui-sans-serif, system-ui, sans-serif")`. Браузер бере шрифт-пару лише для літер, яких бракує, тож латиниця й польські літери лишаються шрифтом сайту. `@theme` і `fonts.ts` сайту не чіпай: на сайт пара не потрапляє. У Manrope немає справжнього курсиву, браузер нахиляє літери сам, для коментарів цього досить.
- Українська в `title` історій і в іменах файлів залишається забороненою (див. «Історія компонента»).

## Історія компонента: одна на компонент

Правило курсу: ОДНА історія на компонент, з панеллю Controls. Не створюй окремих історій Default, Hover, Focus, Disabled.

- Файл `<Компонент>.stories.tsx` лежить поруч із компонентом.
- `title` історії пиши латиницею: `Components/Button`. Кирилицю в `title` не став: з неї виходять кириличні ідентифікатори історій. Українські пояснення клади в опис компонента.
- Перемикачі (`argTypes`) покривають усі варіанти й стани компонента: варіант і розмір через `select`, `disabled` через `boolean`. У поля форми додатково помилка (`boolean`), текст помилки і значення поля. Значення за замовчуванням стоять в `args`.
- Стан «заповнене» в полі форми має перемикатися з Controls. Зміна `defaultValue` у Controls сама поле не оновлює: у `render` історії передай `key={args.defaultValue}`, щоб поле перемальовувалось.
- Стани hover, focus і disabled стилізуються в самому компоненті токенами. Історія їх лише показує, свої стилі в ній не пишуться.
- Навігацію на вузькому екрані студент дивиться через Viewport у тулбарі Storybook. Скажи йому, де ця кнопка. Окремої історії для мобільної версії не створюй.

Приклад (кнопка):

```tsx
import type { Meta, StoryObj } from '@storybook/nextjs-vite';
import { Button } from './Button';

const meta = {
  title: 'Components/Button',
  component: Button,
  tags: ['autodocs'],
  argTypes: {
    variant: { control: 'select', options: ['primary', 'secondary'] },
    size: { control: 'select', options: ['md', 'lg'] },
    disabled: { control: 'boolean' },
  },
  args: { children: 'Написати мені', variant: 'primary', size: 'md', disabled: false },
} satisfies Meta<typeof Button>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Playground: Story = {};
```

Hover і focus. За замовчуванням показуй їх справжніми: компонент в історії живий, студент може навести мишу й пройти клавішею Tab. Це основний спосіб, і він працює завжди. Перемикача hover і focus у панелі Controls немає. Якщо студент хоче перемикач, спробуй аддон `storybook-addon-pseudo-states` (`npx storybook add storybook-addon-pseudo-states`): його перемикач живе в тулбарі Storybook, а не в Controls, а значення за замовчуванням задає `parameters.pseudo`. Спробуй і не стверджуй, що він працює, поки не перевірив у браузері. Якщо не вийшло, лиши справжні hover і Tab та скажи про це студенту. Окремі історії по станах як обхід не створюй.

## Картинки в компонентах

- Картинки компонентів (обкладинка картки тощо) лежать у теці `assets` (наприклад, `src/assets/`) і **імпортуються** в код: `import cover from "@/assets/cover.jpg"`. Файли з `public/` у Storybook не видно, бо `staticDirs` прибрано.
- Картинки з Figma завантажуй у `assets` одразу: посилання, які віддає конектор Figma, живуть кілька днів. Перевір справжній формат файлу: файл із розширенням `.png` буває JPEG. Розширення має відповідати формату.
- Розміри картинок задавай токенами пропорцій (`aspect-cover`), а не висотою в квадратних дужках.

## Документація компонента

Кожен компонент має сторінку docs. Вона потрібна студенту й агентам: за нею Claude розуміє, що це за елемент і як його підключити.

Структура, однакова для всіх компонентів:

- короткий опис: що це і навіщо;
- параметри (пропси) і значення за замовчуванням;
- варіанти і стани;
- токени, які використовує компонент, за іменами;
- коли використовувати, а коли ні;
- як брати в код (короткий приклад).

Зверху опис усього перерахованого, під ним сам компонент з панеллю Controls.

Як зробити: тег `autodocs` у `tags`; JSDoc-коментарі над компонентом і над кожним пропсом; довший опис у `parameters.docs.description.component`. Коли JSDoc не вміщає структуру, зроби MDX-файл: `<Meta of={...} />`, `<Canvas of={...} />`, `<Controls />` (імпорт з `@storybook/addon-docs/blocks`).

Токени називай за іменами: `accent`, `text-muted`, `rounded-control`. Значень (hex, px) не пиши ні в `.tsx`, ні в `.mdx`: вони живуть тільки в `@theme`. Опис пиши так, щоб агент, який прочитав лише його, міг правильно взяти компонент.

## Після кожної зміни компонента або токенів

- Змінив пропси, варіанти, стани чи токени компонента: у тому ж кроці оновлюй історію (`argTypes`, `args`) і docs. Новий варіант без перемикача в Controls і без рядка в документації — не доведена до кінця робота.
- Додав новий компонент: створи історію й docs, а студенту скажи, що розділ «Компоненти» в `CLAUDE.md` треба оновити, і зроби це, якщо він погодиться.
- Змінився `@theme`: онови сторінку «Токени» і скажи студенту, що dev-сервер сайту (`npm run dev`) треба перезапустити: без перезапуску нові класи можуть не з'явитися.
- Перевір, що в змінених файлах немає класів, яких немає в `@theme` (зокрема `text-white`, `bg-black`, `text-sm`), hex і значень у квадратних дужках.

## Збірка для публікації разом із сайтом

Роби це тільки на прохання студента.

1. Storybook збирається в `public/storybook`: `storybook build -o public/storybook`, команда лежить у скрипті `package.json`. Тоді Next.js віддає його за адресою сайту з `/storybook/`.
2. Next.js не віддає `index.html` для теки, тому `/storybook` без цього дає 404. У `next.config.ts` додай `redirects()` з `/storybook` на `/storybook/index.html` (саме redirect, не rewrite: Storybook підключає файли відносними шляхами). Перевір локально: `npm run build`, потім `npm run start` і відкрий `/storybook`.
3. Збірка Storybook має йти раніше за збірку сайту. Приклад скрипта `build`: `storybook build -o public/storybook && next build`. Скажи студенту, що саме ти змінив.
4. Тека `public/storybook` — результат збірки, вручну її не редагуй. Обов'язково додай `public/storybook` у `.gitignore`. Без цього збудований Storybook потрапляє в автоскан файлів Tailwind v4: зʼявляються зайві утиліти, збірка сповільнюється, а в Git потрапляють величезні зміни. Vercel збирає цю теку сам під час деплою.
5. Збери проєкт локально (`npm run build`) і перевір, що файл `public/storybook/index.html` існує. Окремої гілки для цього не створюй.
6. Превʼю, публікація, пуш і перевірка деплою — робота скіла `vercel`. Сам нічого не пушиш і не деплоїш.

## Як перевірити результат

1. Запусти `npm run storybook` і скажи студенту адресу (зазвичай `http://localhost:6006`).
2. Скажи, що перевірити: сторінка «Токени» показує кольори, шрифти й радіуси як у макеті; перемикачі Controls змінюють компонент; наведення миші; Tab показує контур фокусу; вкладка Docs має всі пункти структури; панель Accessibility не показує нових Violations.
3. Панель Accessibility — додаткова перевірка, не вердикт: контраст кольорів студент звіряє у WebAIM Contrast Checker.
4. Не стверджуй, що все виглядає правильно, якщо сам цього не бачив: попроси студента подивитись і описати.
5. `npm run build` має проходити без помилок. Якщо перевірка типів падає з посиланням на файл, якого вже немає (`Cannot find module …` у `.next/types`), видали теку `.next` і збери знову.

## Чого цей скіл не робить

- Не публікує і не пушить (це скіл `vercel`).
- Не створює гілок.
- Не створює тимчасових сторінок-перевірок на сайті: усе показується в Storybook.
- Не підключає MCP-сервери (Storybook MCP, Vercel MCP).
- Не створює окремих історій по станах.
- Не змінює токени в `@theme` заради історії чи документації.
- Не ставить Vitest, Playwright, Chromatic і MCP; не додає тести й візуальні регресійні перевірки.
- Скіл це інструкція в контексті сесії, а не примус: Claude може відступити від неї, тому результат перевіряй сам. Розсинхрон шукай запитом із розділу «Три способи побачити розсинхрон» у занятті 6.
